# راجع بذكاء

منصة تعليمية عربية لتلاميذ التعليم الثانوي في الجزائر.

## تشغيل الموقع

الموقع واجهة ثابتة مناسبة لـ GitHub Pages. ملف الدخول هو `index.html`.

1. افتح إعدادات المستودع في GitHub ثم **Pages** واختر النشر من الفرع `main` والمجلد `/ (root)`.
2. رابط الموقع: https://bouafiazakaria71-png.github.io/smart-revision-hub/

## ربط Supabase (تم إعداد ملفات الموقع)

تم إنشاء مشروع Supabase وربط إعداداته العامة في `config.js` بالفعل:

- Project URL: `https://fxrfxilxbxrkxadgfkxw.supabase.co`
- المفتاح المستخدم في المتصفح هو **Publishable key** فقط.
- تم تنفيذ `supabase-schema.sql` والتحقق من ظهور الجدولين `profiles` و`study_resources`.

لا تستبدل الإعدادات الحالية في `config.js` إلا عند تغيير مشروع Supabase. لا تضف مطلقًا مفتاح `Secret` أو `service_role` إلى ملفات GitHub.

## تفعيل تسجيل الدخول بالبريد وGoogle

### إعداد عناوين العودة في Supabase

1. افتح **Authentication → URL Configuration**.
2. ضع عنوان الموقع التالي في **Site URL**:
   `https://bouafiazakaria71-png.github.io/smart-revision-hub/`
3. أضف العنوان نفسه إلى **Redirect URLs** واحفظ.

### إعداد Google OAuth

يلزم إنشاء بيانات OAuth في حساب Google ثم حفظها في لوحة Supabase؛ لا يحتاج الموقع إلى Client Secret في ملفاته.

1. افتح [Google Cloud Console](https://console.cloud.google.com/) وأنشئ OAuth Client من نوع **Web application**.
2. في **Authorized JavaScript origins** أضف:
   `https://bouafiazakaria71-png.github.io`
3. في **Authorized redirect URIs** أضف عنوان Callback الذي يعرضه Supabase في **Authentication → Sign In / Providers → Google**. لمشروعك يكون عادةً:
   `https://fxrfxilxbxrkxadgfkxw.supabase.co/auth/v1/callback`
   استخدم القيمة التي يعرضها Supabase إذا اختلفت.
4. أنشئ OAuth Client وانسخ **Client ID** و**Client Secret**.
5. ارجع إلى Supabase وافتح **Authentication → Sign In / Providers → Google**، فعّل Google، ثم أدخل Client ID وClient Secret واحفظ.
6. إذا كان تطبيق Google في وضع الاختبار، أضف حسابات الاختبار المسموح لها بتجربة الدخول في إعدادات Google OAuth.

بعد حفظ الإعدادات، افتح الموقع واضغط «المتابعة باستخدام Google» لاختبار تسجيل الدخول. لا ترسل Client Secret أو كلمات المرور أو مفاتيح Secret إلى أي شخص.

## حساب المسؤول

بعد إنشاء حسابك وتأكيد البريد الإلكتروني، عيّن حسابك مسؤولًا من **SQL Editor** باستخدام الاستعلام الموجود في نهاية `supabase-schema.sql` بعد استبدال `YOUR_ADMIN_EMAIL` ببريد حسابك. نفّذ هذا الاستعلام بنفسك من لوحة Supabase، ولا تمنح دور المسؤول لأي حساب آخر دون حاجة.

## مكوّنات الأمان

- Supabase Auth يتولى التحقق من كلمات المرور وإدارة الجلسات والرموز وتجديدها.
- الواجهة تستخدم المفتاح العام فقط. المفتاح العام ليس سرًا، لكن يجب حماية البيانات بسياسات RLS.
- لا تضع أبدًا `service_role` أو مفاتيح مزوّد الذكاء الاصطناعي في `index.html` أو `config.js`.
- صلاحية المسؤول تُقرأ من جدول profiles، وعمليات إضافة الموارد محمية بسياسات RLS في قاعدة البيانات.
- تغيير دور المستخدم محظور من واجهة المستخدم بواسطة trigger. غيّر الدور إداريًا من SQL Editor فقط.
- استخدم HTTPS، فعّل تأكيد البريد، واضبط قيود كلمات المرور والحماية من إساءة الاستخدام في إعدادات Supabase.
- أُضيفت Edge Function باسم `study-assistant` لمعالجة الأسئلة والتلخيص عبر خادم آمن. لا يوضع مفتاح مزوّد الذكاء الاصطناعي في ملفات المتصفح أو GitHub.

## تشغيل مساعد الذكاء الاصطناعي المجاني

يعتمد المساعد الآن على تشغيل نموذج مفتوح المصدر داخل متصفح الطالب باستخدام **WebLLM وWebGPU** بدلاً من إرسال كل سؤال إلى واجهة API مدفوعة.

### النماذج المتاحة

- **Qwen3 1.7B**: النموذج الافتراضي الموصى به، ويحتاج إلى جهاز بذاكرة رسومية مناسبة.
- **Qwen3 0.6B**: خيار أخف إذا كان الجهاز لا يستطيع تحميل النموذج الأكبر، مع مستوى إجابة أبسط.

### طريقة التشغيل

1. افتح الموقع من رابط GitHub Pages باستخدام أحدث إصدار من Chrome أو Edge.
2. انتقل إلى قسم «مساعد راجع بذكاء».
3. اختر النموذج المناسب لجهازك، ثم اضغط «تحميل النموذج المجاني».
4. انتظر اكتمال التنزيل والتهيئة في أول استخدام؛ قد يستغرق ذلك وقتاً ويستهلك مساحة من ذاكرة المتصفح.
5. بعد ظهور «النموذج جاهز»، اكتب السؤال أو اختر درساً واستخدم أزرار «لخّص الدرس» و«اختبر فهمي» و«اشرح الدرس» و«الدردشة مع المساعد الذكي».

### المجانية والحدود الواقعية

- لا يحتاج المسار المحلي إلى `OPENAI_API_KEY`، ولا يستهلك طلبات من OpenAI، ولا يفرض حداً يومياً من جهة خادم المنصة.
- تتم معالجة السؤال داخل جهاز الطالب؛ ولا يُرسل نص الدرس المستخرج إلى مزوّد نموذج سحابي.
- يلزم الإنترنت في أول تحميل للمكتبات والنموذج. يحاول المتصفح الاحتفاظ بملفات النموذج في التخزين المؤقت لاستخدامها لاحقاً، لكن المتصفح قد يحذفها أو يطلب تنزيلها مجدداً.
- يعتمد الأداء على المعالج الرسومي والذاكرة والتبريد ومساحة التخزين. لذلك لا يمكن ضمان سرعة أو جودة واحدة على جميع الأجهزة، ولا يمكن وصفه بأنه أقوى من النماذج السحابية أو بأنه غير محدود تقنياً.
- يتطلب WebGPU ومتصفحاً متوافقاً؛ إذا لم يعمل النموذج الأكبر فاختر Qwen3 0.6B. وقد لا يعمل على بعض الأجهزة القديمة أو عند تعطيل تسريع الرسوميات.

### قراءة ملفات الدروس

- عند اختيار مورد يحتوي على PDF من مخزن `study-pdfs`، يجلب المتصفح الملف ويستخرج النص محلياً باستخدام PDF.js، ثم يمرر مقتطفاً محدوداً إلى النموذج.
- يقتصر الاستخراج في هذه النسخة على أول 30 صفحة وبحد أقصى 4200 حرف. الملفات الممسوحة ضوئياً كصور أو المحمية بكلمة مرور قد لا يُستخرج نصها.
- إذا لم يوجد PDF أو تعذر استخراج النص، يجب على المساعد التصريح بذلك والاعتماد فقط على العنوان والوصف والأسئلة المتاحة، لا الادعاء بأنه قرأ محتوى الملف.

### ملاحظة عن الإعداد القديم

تظل Edge Function القديمة `study-assistant` موجودة في Supabase، لكن واجهة الموقع لا تستدعيها في مسار الدردشة المحلي الجديد. لا تحتاج إلى إنشاء مفتاح OpenAI أو إضافة سر `OPENAI_API_KEY` لتشغيل هذا المسار. كما أن جدول الحد اليومي القديم لم يعد يحدد استخدام المساعد المحلي.

## الملفات

- `index.html`: الواجهة المتجاوبة وسلوك الأزرار والنماذج.
- `config.js`: إعدادات Supabase العامة (المفتاح العام فقط).
- `supabase-schema.sql`: الجداول وسياسات الوصول والتريغرات.

## ملاحظات

- لا تضع بيانات حقيقية أو أسرارًا في المستودع العام.
- قبل إطلاق المنصة للجمهور، اختبر التسجيل وتأكيد البريد واستعادة كلمة المرور وتسجيل الخروج وصلاحيات المسؤول.
 
## لوحة المسؤول: المحتوى والطلاب

تمت إضافة إمكانات إدارة المحتوى في الواجهة: إضافة الدروس والملخصات والتمارين، تعديلها وحذفها، إرفاق فيديو شرح، رفع PDF (حتى 20 ميغابايت)، وإضافة أسئلة اختيار من متعدد مع التصحيح والتفسير. كما تعرض لوحة المسؤول حسابات الطلاب وتسمح بتحديث الاسم والشعبة.

### ترقية مشروع Supabase الموجود

لأن مشروع Supabase لديك سبق أن نفّذ المخطط القديم، افتح **SQL Editor** ونفّذ محتوى الملف `supabase-admin-upgrade.sql` مرة واحدة. ينشئ هذا التحديث حقول البريد والفيديو والأسئلة وسياسات قراءة حسابات الطلاب، ويجهز مخزن ملفات PDF. لا تعِد تشغيل المخطط القديم فوق مشروع حي لمجرد التحديث.

### تفعيل حساب المسؤول

بعد تسجيل الدخول إلى الموقع بحسابك، نفّذ في SQL Editor الاستعلام التالي مع استبدال البريد بعنوان حساب الدخول الخاص بك:

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'YOUR_LOGIN_EMAIL');
```

تحقق من أن صفًا واحدًا قد تم تحديثه. لا ترسل كلمة المرور أو أي مفتاح Secret. لا يصبح الحساب مسؤولًا بمجرد نشر الملفات؛ يجب تنفيذ الاستعلام أعلاه يدويًا بعد إنشاء الحساب.

### حدود إدارة حسابات الطلاب

تتيح اللوحة الاطلاع على بريد الطالب واسمه وشعبته وتعديل الاسم والشعبة. لا يمكن للمتصفح إيقاف حساب Auth أو حذفه بأمان؛ ذلك يتطلب Edge Function موثوقة تتحقق من هوية المسؤول وتستخدم صلاحيات الخادم دون كشف مفتاح service_role.
