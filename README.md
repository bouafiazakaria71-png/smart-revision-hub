# راجع بذكاء

منصة تعليمية عربية لتلاميذ التعليم الثانوي في الجزائر.

## تشغيل الموقع

الموقع واجهة ثابتة منشورة عبر Cloudflare Pages، وملف الدخول هو `index.html`.

- رابط الطلاب: https://ali-ibn-abi-talib-smart-revision-hub.pages.dev/student/
- رابط المسؤول: https://ali-ibn-abi-talib-smart-revision-hub.pages.dev/admin/
- العنوان الأساسي `/` يحوّل الزائر تلقائياً إلى بوابة الطلاب.
- بوابة الطلاب لا تعرض لوحة المسؤول أو أدوات الإدارة حتى لو كان المسؤول قد سجّل الدخول من الجهاز نفسه.
- بوابة المسؤول لا تسمح بإنشاء حساب جديد؛ تتطلب تسجيل الدخول بحساب يحمل دور `admin` في جدول `profiles`. أي حساب طالب يحاول فتحها يُعاد إلى بوابة الطلاب.

### إعداد Cloudflare Pages الدقيق

- Git repository: `bouafiazakaria71-png/smart-revision-hub`
- Production branch: `main`
- Framework preset: `None`
- Build command: `exit 0`
- Build output directory: `.`
- Root directory: اتركه فارغاً (جذر المستودع).
- لا تنشئ ملف `404.html` في جذر المشروع. يحتوي المستودع على Pages Function داخل `functions/api/study-assistant.js`، لذلك يجب أن يبقى مجلد `functions` في جذر المشروع وأن يكون مجلد الإخراج هو `.`.

ملف `_redirects` يوجّه `/` إلى بوابة الطلاب ويخدم `/student/` و`/admin/` من ملف `index.html` مع إبقاء المسار ظاهراً في شريط العنوان.

## ربط Supabase (تم إعداد ملفات الموقع)

تم إنشاء مشروع Supabase وربط إعداداته العامة في `config.js` بالفعل:

- Project URL: `https://fxrfxilxbxrkxadgfkxw.supabase.co`
- المفتاح المستخدم في المتصفح هو **Publishable key** فقط.
- تم تنفيذ `supabase-schema.sql` والتحقق من ظهور الجدولين `profiles` و`study_resources`.

لا تستبدل الإعدادات الحالية في `config.js` إلا عند تغيير مشروع Supabase. لا تضف مطلقًا مفتاح `Secret` أو `service_role` إلى ملفات GitHub.

## ربط المساعد الذكي في Cloudflare Pages

توجد دالة Pages في `functions/api/study-assistant.js` وتُستدعى من الواجهة عبر `/api/study-assistant`. كي تعمل، أضف Workers AI Binding إلى مشروع Pages:

1. افتح **Workers & Pages** ثم مشروع Pages الخاص بالمنصة.
2. افتح **Settings → Functions → Bindings**.
3. ضمن بيئة **Production** اختر **Add → Workers AI**.
4. اكتب **Variable name** بالقيمة الدقيقة `AI` ثم احفظ.
5. أعد نشر المشروع بعد حفظ الربط. أضف الربط إلى **Preview** أيضاً فقط عند الحاجة لاختبار نسخ المعاينة.

اسم الربط حساس: الكود يستدعي `env.AI.run(...)`، لذا لا تستخدم اسماً آخر. عند غياب الربط سترجع الدالة رسالة إعداد واضحة بدلاً من إجابة المساعد. قد يخضع استهلاك Workers AI لحدود أو رسوم الحساب؛ راجع صفحة الاستخدام والتسعير مع ولي الأمر قبل تفعيل أي استخدام مدفوع.

## تفعيل تسجيل الدخول بالبريد وGoogle

### إعداد عناوين العودة في Supabase

1. افتح **Authentication → URL Configuration**.
2. ضع بوابة الطلاب في **Site URL**:
   `https://ali-ibn-abi-talib-smart-revision-hub.pages.dev/student/`
3. أضف العنوانين التاليين إلى **Redirect URLs** واحفظ:
   - `https://ali-ibn-abi-talib-smart-revision-hub.pages.dev/student/`
   - `https://ali-ibn-abi-talib-smart-revision-hub.pages.dev/admin/`

### إعداد Google OAuth

يلزم إنشاء بيانات OAuth في حساب Google ثم حفظها في لوحة Supabase؛ لا يحتاج الموقع إلى Client Secret في ملفاته.

1. افتح [Google Cloud Console](https://console.cloud.google.com/) وأنشئ OAuth Client من نوع **Web application**.
2. في **Authorized JavaScript origins** أضف:
   `https://ali-ibn-abi-talib-smart-revision-hub.pages.dev`
3. في **Authorized redirect URIs** أضف عنوان Callback الذي يعرضه Supabase في **Authentication → Sign In / Providers → Google**. لمشروعك يكون عادةً:
   `https://fxrfxilxbxrkxadgfkxw.supabase.co/auth/v1/callback`
   استخدم القيمة التي يعرضها Supabase إذا اختلفت.
4. أنشئ OAuth Client وانسخ **Client ID** و**Client Secret**.
5. ارجع إلى Supabase وافتح **Authentication → Sign In / Providers → Google**، فعّل Google، ثم أدخل Client ID وClient Secret واحفظ.
6. إذا كان تطبيق Google في وضع الاختبار، أضف حسابات الاختبار المسموح لها بتجربة الدخول في إعدادات Google OAuth.

بعد حفظ الإعدادات، افتح الموقع واضغط «المتابعة باستخدام Google» لاختبار تسجيل الدخول. لا ترسل Client Secret أو كلمات المرور أو مفاتيح Secret إلى أي شخص.

## حساب المسؤول

بعد إنشاء حسابك وتأكيد البريد الإلكتروني، عيّن حسابك مسؤولًا من **SQL Editor** باستخدام الاستعلام الموجود في نهاية `supabase-schema.sql` بعد استبدال `YOUR_ADMIN_EMAIL` ببريد حسابك. نفّذ هذا الاستعلام بنفسك من لوحة Supabase، ولا تمنح دور المسؤول لأي حساب آخر دون حاجة.

## مكوّنات الأمان

- Supabase Auth يتولى التحقق من كلمات المرور وإدارة الجلسات والرموز وتجديدها.
- الواجهة تستخدم المفتاح العام فقط. المفتاح العام ليس سرًا، لكن يجب حماية البيانات بسياسات RLS.
- لا تضع أبدًا `service_role` أو مفاتيح مزوّد الذكاء الاصطناعي في `index.html` أو `config.js`.
- بيانات الطالب وسجلات تقدمه مقيدة بسياسات RLS؛ يقرأ الطالب بياناته فقط، وتُمنح صلاحيات الإدارة لحساب يحمل دور `admin` المحمي داخل قاعدة البيانات.
- تم تعطيل شرط Cloudflare Turnstile مؤقتًا للاختبار عبر `ADMIN_CAPTCHA_ENABLED=false` داخل `index.html`. يظل تسجيل الدخول بحساب المسؤول ودور `admin` وسياسات قاعدة البيانات مطلوبًا.
- لا يستطيع المستخدم تغيير دوره أو بريده من واجهة المتصفح؛ يتطلب تعديل الدور إجراءً إداريًا من SQL Editor.
- واجهة التسجيل تشترط كلمة مرور من 12 حرفًا على الأقل. أكمِل أيضاً إعداد الحد الأدنى لكلمة المرور ومنع كلمات المرور المسرّبة من لوحة Supabase (Authentication → Settings / Password Security)، لأن تحقق الواجهة وحده ليس حماية خادمية.
- ملفات `_headers` تضيف ترويسات أمان وسياسة CSP إلى Cloudflare Pages. ملفات PDF في مخزن `study-pdfs` عامة للقراءة حتى يتمكن الطلاب من فتح الدروس؛ ارفع مواد تعليمية عامة فقط ولا ترفع ملفات شخصية أو سرية.
- دالة `study-assistant` تعمل عبر Cloudflare Pages Function. لا يوضع مفتاح `service_role` أو مفتاح سري لمزوّد الذكاء الاصطناعي في ملفات المتصفح أو GitHub.

## حماية بوابة المسؤول باستخدام Cloudflare Turnstile

أنشئ Widget في Cloudflare Turnstile وحدد اسم المضيف `ali-ibn-abi-talib-smart-revision-hub.pages.dev` (وأي نطاق مخصص تستخدمه لاحقًا). اختر الوضع Managed.

1. انسخ **Site Key** العام إلى المتغير `TURNSTILE_SITE_KEY` في `config.js`؛ هذا المفتاح ليس سريًا.
2. في **Cloudflare → Workers & Pages → مشروع Pages → Settings → Variables and Secrets** أضف **Secret** باسم `TURNSTILE_SECRET_KEY` وضع فيه **Secret Key** الخاص بالـ Widget. لا تضعه في GitHub أو `config.js`.
3. أعد نشر فرع `main` بعد ضبط المفتاحين. تتحقق الدالة `functions/api/admin-captcha.js` من الرمز عبر Siteverify، وتتحقق من اسم المضيف واسم الإجراء `admin_access`.
4. إذا ظهر تنبيه بأن إعداد CAPTCHA غير مكتمل، فتحقق من وجود Site Key في `config.js` وSecret في بيئة Production.

الكابتشا معطلة حاليًا للاختبار. لإعادة تفعيلها بعد إعداد المفتاحين، غيّر `ADMIN_CAPTCHA_ENABLED` إلى `true` في `index.html` ثم انشر تحديثًا جديدًا. تبقى دالة التحقق والواجهة وإعدادات Turnstile محفوظة. عند تفعيلها، تستمر صلاحية الاختبار 20 دقيقة.

## تشغيل المساعد الذكي عبر Cloudflare

تعمل واجهة المساعد عبر Cloudflare Pages Function الموجودة في `functions/api/study-assistant.js`، وتستخدم Workers AI بالنموذج `@cf/google/gemma-4-26b-a4b-it`. لا يحتاج هذا الإعداد إلى وضع مفتاح سري في ملفات المتصفح أو المستودع.

### إعداد الربط
1. افتح **Cloudflare → Workers & Pages → مشروع Pages**.
2. افتح **Settings → Functions → Bindings**.
3. أضف **Workers AI Binding** باسم المتغير الدقيق `AI` إلى بيئة Production.
4. احفظ ثم أعد نشر الموقع. أضف الربط إلى Preview فقط عند اختبار نسخة المعاينة.

### حد الاستخدام وحماية الطلبات
- لكل حساب مسجل حد أقصى **25 طلباً للمساعد يومياً**. يُحفظ العداد في `ai_usage_daily` بسياسات RLS، ولا يستطيع الطالب قراءة عداد حساب آخر أو إرجاعه إلى الصفر.
- لا يرسل المتصفح مفتاح `service_role` أو أي سر لخدمة الذكاء الاصطناعي.
- يتحقق الخادم من جلسة Supabase، ومصدر الطلب، وصحة حجم البيانات، ومن تطابق الدرس المحدد مع مستوى الطالب وشعبته.
- أزرار «اشرح الدرس ولخّصه» و«اختبر فهمي» والأسئلة النصية تستخدم الدالة نفسها. يحاول الموقع استخراج نص PDF المحدد قبل إرساله؛ ولا يدّعي قراءة ملف مصوّر لا يمكن استخراج نصه.
- يُرسل سؤال الطالب ومقتطف الدرس إلى خدمة الاستدلال لمعالجته. لا تضع في الدروس أو المحادثات بيانات شخصية أو معلومات سرية.

## تصوير الفرض اعتماداً على الدروس والملخصات

- تظهر أداة **تصوير الفرض** في بوابة الطلاب، ويمكن فتح الكاميرا على الهاتف أو اختيار صورة JPG أو PNG أو WebP من الحاسوب.
- يختار الطالب حتى خمسة موارد من نوع «درس» أو «ملخص» فقط، وتتحقق الواجهة والخادم من نوع المورد ومن تطابق المستوى والشعبة. تُقرأ ملفات PDF النصية (حتى أول 18 صفحة و14 ألف حرف تقريباً) ويُرسل مقتطف من كل مرجع مع صورة الفرض إلى نموذج Gemma 4 Vision.
- يلتزم المساعد بالمراجع المحددة فقط، ويشرح خطوات الحل حسب ترتيب الأسئلة. عندما لا تتضمن المراجع معلومة كافية أو تكون الصورة غير واضحة، يجب أن يصرّح بذلك بدل التخمين.
- يتحقق الخادم من جلسة الحساب ومعرّفات الموارد، ومن تطابق المستوى والشعبة للطالب. حد الصورة بعد الضغط 1.5 ميغابايت، والطلب يستخدم العداد اليومي نفسه للمساعد (25 طلبًا للحساب يوميًا).
- لا تُحفظ صورة الفرض في جدول أو مخزن الموقع؛ تُرسل لمعالجتها عبر Cloudflare Workers AI. لا ترفع صورًا تحتوي على أسماء أو بيانات شخصية غير لازمة.
- ملفات PDF المصوّرة التي لا تحتوي على نص قابل للاستخراج قد لا تصلح كمراجع في هذه النسخة؛ استخدم PDF نصيًا أو أضف ملخصًا مكتوبًا في وصف المورد. المساعد لا يستخرج نصوص OCR من صفحات PDF الممسوحة ضوئياً تلقائياً.

## الملفات

- `index.html`: الواجهة المتجاوبة وسلوك الأزرار والنماذج.
- `_redirects`: توجيه الزائر إلى بوابة الطلاب والفصل بين مساري الطالب والمسؤول.
- `_headers`: ترويسات الأمان وسياسة Content Security Policy.
- `functions/api/study-assistant.js`: المساعد الذكي على خادم Cloudflare Pages.
- `functions/api/admin-captcha.js`: التحقق الخادمي من Cloudflare Turnstile لبوابة المسؤول.
- `config.js`: إعدادات Supabase العامة (المفتاح العام فقط).
- `supabase-schema.sql`: الجداول وسياسات الوصول والتريغرات.
- `supabase-lesson-quiz-upgrade.sql`: جدول بنك الأسئلة وجدول تقدم الطالب ومحاولاته.
- `supabase-student-analytics-upgrade.sql`: مستوى الطالب ومزامنة البريد وسياسة قراءة التقدم للمسؤول وتفعيل Realtime.
- `supabase-security-hardening.sql`: حماية سياسات RLS وصلاحيات المسؤول وحد الاستخدام اليومي للمساعد.

## ملاحظات

### بوابة المسؤول واختبار CAPTCHA

- حاليًا، عند فتح `/admin/`، يكفي تسجيل الدخول بحساب المسؤول المعتمد؛ شرط CAPTCHA معطل مؤقتًا عبر `ADMIN_CAPTCHA_ENABLED=false` للاختبار.
- مدة نجاح الاختبار 20 دقيقة داخل التبويب؛ بعدها يظهر الاختبار مرة أخرى.
- مفتاح Site Key العام يُحفظ في `TURNSTILE_SITE_KEY` داخل `config.js`، بينما Secret Key يبقى سرًا باسم `TURNSTILE_SECRET_KEY` في إعدادات Cloudflare Pages.
- صلاحيات قاعدة البيانات تتحقق من دور `admin` المحمي؛ CAPTCHA طبقة لتقليل الدخول الآلي ولا تستبدل كلمة المرور أو حماية الجلسة.

### تحديث أمان قاعدة البيانات

نفّذ محتوى `supabase-security-hardening.sql` مرة واحدة في **Supabase → SQL Editor** بعد مخططات الجداول والتوسعات. يحوّل صلاحيات المسؤول إلى دالة خاصة تتحقق من دور الحساب المحمي، ويجمع سياسة قراءة تقدم الطالب لتجنب التكرار، ويضيف عداد استخدام يومياً للمساعد. هذا التحديث مطبّق على مشروع Supabase الحالي؛ احتفظ بالملف لإعداد نسخ جديدة.

**إعدادات إضافية مطلوبة في لوحة Supabase قبل الإطلاق:** فعّل Email confirmation، وLeaked Password Protection، وحدد الحد الأدنى لكلمة المرور 12 حرفاً أو أكثر، وراجع حدود Auth وCAPTCHA وSMTP. هذه الإعدادات لا تُدار من ملفات الموقع وحدها.


- لا تضع بيانات حقيقية أو أسرارًا في المستودع العام.
- قبل إطلاق المنصة للجمهور، اختبر التسجيل وتأكيد البريد واستعادة كلمة المرور وتسجيل الخروج وصلاحيات المسؤول.
 
## لوحة المسؤول: المحتوى والطلاب

تظهر أدوات إضافة المحتوى في **لوحة المسؤول** فقط. بعد تسجيل الدخول بالحساب الذي يحمل صلاحية `admin`، افتح رابط **إدارة المحتوى** في شريط التنقل. ستجد مكانين منفصلين:

- **إضافة درس**: اضغط «إضافة درس جديد»، ثم أدخل العنوان والمادة والمستوى والشعبة، وارفع ملف PDF (حتى 20 ميغابايت). يمكن إرفاق فيديو الشرح، أما الأسئلة فتُضاف لاحقاً من بنك الأسئلة المستقل. ويمكنك اختيار «ملخص» من نوع المحتوى لإضافة ملخص مستقل.
- **رفع حولية**: اضغط «رفع حولية جديدة»، ثم أدخل بيانات المادة والمستوى والشعبة وارفع ملف PDF. لا تظهر حقول الفيديو والأسئلة عند اختيار الحولية.

يظهر المحتوى المنشور في المكتبة الدراسية للطلاب، ويمكن للمسؤول تعديله أو حذفه من بطاقة المورد. تعرض لوحة المسؤول حسابات الطلاب وتسمح بتحديث الاسم والمستوى والشعبة. أنواع المحتوى المتاحة حالياً: درس، ملخص، تمرين، حولية. حقل الفيديو يقبل رابط فيديو خارجي؛ رفع ملفات الفيديو مباشرة إلى تخزين المنصة غير مفعّل حالياً.

### ترقية مشروع Supabase الموجود

لأن مشروع Supabase لديك قائم بالفعل، لا تُعد تشغيل المخطط الأساسي على قاعدة حية. التوسعات منفصلة حسب الحاجة: `supabase-lesson-quiz-upgrade.sql` لبنك الأسئلة والتقدم، و`supabase-student-analytics-upgrade.sql` لملف المستوى ومراقبة التقدم. هذان التحديثان مطبّقان على المشروع الحالي.

### تفعيل حساب المسؤول

بعد تسجيل الدخول إلى الموقع بحسابك، نفّذ في SQL Editor الاستعلام التالي مع استبدال البريد بعنوان حساب الدخول الخاص بك:

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'YOUR_LOGIN_EMAIL');
```

تحقق من أن صفًا واحدًا قد تم تحديثه. لا ترسل كلمة المرور أو أي مفتاح Secret. لا يصبح الحساب مسؤولًا بمجرد نشر الملفات؛ يجب تنفيذ الاستعلام أعلاه يدويًا بعد إنشاء الحساب.

### بنك الأسئلة التدريبية ومسار الطالب

أُضيف قسم مستقل باسم **بنك الأسئلة التدريبية** داخل لوحة المسؤول:

1. أضف الدرس أولاً من بطاقة **إضافة درس** وحدد المادة والمستوى والشعبة.
2. افتح **بنك الأسئلة التدريبية**، واختر الدرس من القائمة؛ يظهر اسم المادة والدرس والمستوى لتتأكد من الربط الصحيح.
3. اكتب السؤال وأدخل أربعة خيارات وحدد الإجابة الصحيحة، ويمكنك إضافة شرح للتصحيح، ثم اضغط **حفظ السؤال في هذا الدرس**. كرر ذلك لإضافة بقية الأسئلة. يمكن حذف الأسئلة من قائمة الدرس.
4. في بطاقة الدرس لدى الطالب، يفتح ملف PDF أو فيديو الشرح، ثم يضغط **أتممت المراجعة**. عندها يظهر زر **اختبرني في هذا الدرس** الخاص بالدرس نفسه.
5. يعرض الاختبار سؤالاً في كل مرة، وبعد الإنهاء تظهر النتيجة والإجابات الصحيحة والتفسيرات. تُحفظ المحاولات وأفضل نتيجة في حساب الطالب عند تسجيل الدخول؛ وللزائر تحفظ على الجهاز الحالي.

الأسئلة الجديدة تُخزّن منفصلة في `study_questions` وترتبط بمعرّف الدرس، بينما يُخزّن تقدم الطالب في `lesson_progress`. لا تحتاج إلى إدخال الأسئلة داخل نموذج إضافة ملف الدرس.

### ترقية قاعدة البيانات لبنك الأسئلة

- أُنشئ جدول `study_questions` وجدول `lesson_progress` وسياسات RLS والفهارس في مشروع Supabase المرتبط بالموقع.
- ملف `supabase-lesson-quiz-upgrade.sql` يوثق التحديث ويمكن استخدامه عند إعداد نسخة جديدة من المشروع. **التحديث مطبّق بالفعل على مشروع Supabase الحالي**.

### لوحة متابعة تقدم الطلاب

- لا تُدرج الزيارات المجهولة أو الضيوف كحسابات طلاب؛ تعرض القائمة الحسابات المسجلة التي يحمل ملفها دور `student` فقط.
- عند إنشاء حساب بالبريد، يطلب النموذج الاسم والمستوى الدراسي والشعبة. عند استخدام Google يمكن للطالب تحديد مستواه وشعبته من أزرار المستوى في بوابة الطلاب، ويحفظ الاختيار في ملفه.
- يظهر البريد من `profiles.email`، ويُزامن مع البريد المسجل لدى Supabase Auth عند إنشاء الحساب أو تغييره. يمكن للمسؤول تعديل الاسم والمستوى والشعبة، وليس البريد أو دور الحساب.
- تعرض اللوحة عدد الطلاب النشطين في المراجعة، محاولات الاختبار، متوسط آخر النتائج وأفضل نتيجة، وآخر نشاط دراسي مسجل.
- **نسبة إنجاز الدروس** تساوي عدد الدروس المنشورة المطابقة لمستوى الطالب وشعبته التي سجل إتمام مراجعتها، مقسوماً على عدد الدروس المنشورة المطابقة. لا تعرض نسبة مضللة عند غياب المستوى أو الشعبة أو عدم وجود دروس مناسبة؛ تظهر حينها «—».
- زر **التفاصيل** يعرض كل درس مناسب وحالة مراجعته وعدد محاولات الاختبار وآخر نتيجة وأفضل نتيجة.
- تُحدّث لوحة المسؤول آلياً عند إضافة حساب طالب أو تسجيل تقدم جديد عبر Supabase Realtime، مع زر تحديث يدوي احتياطي.
- البريد والتقدم محميان بسياسات RLS: الطالب يرى سجلاته الشخصية، والمسؤول المعتمد فقط يستطيع قراءة قائمة الطلاب وتقدمهم. لا تُقرأ كلمات المرور أو تعرض أو تخزن في لوحة المسؤول أو جدول `profiles`.
- النشاط الأخير المعروض هو **آخر نشاط تعليمي مسجل** في جدول التقدم، وليس تتبعاً لكل حركة أو نقرة داخل الموقع.

لتطبيق تحديث قاعدة البيانات على مشروع Supabase الحالي، افتح **SQL Editor** ونفّذ محتوى `supabase-student-analytics-upgrade.sql` مرة واحدة. هذا التحديث يضيف حقل المستوى، يزامن بريد الحساب، ويمنح المسؤول قراءة التقدم ويضيف الجدولين إلى Realtime. التحديث مطبق بالفعل على المشروع المرتبط حالياً.

لا تنفّذ إيقاف حساب Auth أو حذفه مباشرة من المتصفح؛ أي إدارة لحالة حسابات Auth مستقبلاً يجب أن تمر عبر دالة خادمية موثوقة تتحقق من هوية المسؤول ولا تكشف مفتاح `service_role`.
